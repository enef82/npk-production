# 0004. UUIDv7 через библиотеку `uuid6`, а не stdlib

## Контекст

`core.common.UUIDPrimaryKeyModel` — базовый PK-миксин для будущих моделей всех модулей —
использует UUIDv7 (RFC 9562): монотонно возрастающие по времени UUID лучше ложатся в
B-tree индекс Postgres, чем случайный UUIDv4. Python 3.14 добавил `uuid.uuid7()` в стандартный
модуль `uuid`, и Django 5.2.17, psycopg 3.3.4, django-ninja 1.6.3 уже официально поддерживают
3.14 — казалось бы, апгрейд рантайма с 3.13 закрывает вопрос без единой новой зависимости.
Проверка остальных пинов на PyPI на момент задачи показала, что `celery==5.6.3` — версия,
уже зафиксированная в проекте, — 3.14 в classifiers не заявляет: только до 3.13.

## Решение

Пока `celery` не объявит поддержку 3.14, PK остаётся на Python 3.13 и библиотеке
`uuid6==2025.0.1` (чистый Python, без зависимостей, `uuid6.uuid7()` возвращает обычный
`uuid.UUID`, реализация RFC 9562 — поведение идентично будущему stdlib-варианту). Апгрейд
рантайма ради одной функции стандартной библиотеки не стоит риска — он потянул бы за собой
пересборку Dockerfile, CI и проверку совместимости всех остальных пинов на непроверенной
комбинации версий, а причина внедрения (`UUIDPrimaryKeyModel`) на выбор библиотеки почти не
влияет: интерфейс `uuid7() -> UUID` одинаков что у `uuid6`, что у stdlib.

**Триггер пересмотра:** как только `celery` официально объявит поддержку Python 3.14
(появится `Programming Language :: Python :: 3.14` в classifiers очередного релиза на PyPI,
а не только формальная совместимость через `requires-python`), — переходим на `uuid.uuid7()`
из stdlib и удаляем зависимость `uuid6` из `pyproject.toml`. Изменение локально:
`src/core/common/models.py` (`from uuid6 import uuid7` → `from uuid import uuid7`) и обновление
`requires-python` в `pyproject.toml`.

## Отвергнутые альтернативы

- **`uuid-utils`** (Rust-backed) — быстрее, но возвращает собственный тип UUID, а не
  `uuid.UUID` (совместимость вынесена в отдельный подмодуль `uuid_utils.compat`); добавляет
  бинарную зависимость, что усложняет сборку и непредсказуемо для команды из 1-2 человек.
  Для PK, где не требуется массовая генерация вне БД, выигрыш в скорости не оправдывает риск.
- **Апгрейд на Python 3.14 сейчас** — отклонён из-за `celery==5.6.3`, см. выше.
